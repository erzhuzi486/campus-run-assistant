# 校园跑 · 定位与相机调试工具

在**雷电模拟器**里跑校园跑类 App 的一套工具：把 GPS 坐标按 1 Hz 投喂进虚拟机，
让 App 认为你在操场上跑圈；同时提供一套**相机链路诊断工具**，用来判断模拟器里的
相机画面到底是"真电脑摄像头"还是"内置合成场景"。

> 本项目只做**本机模拟器调试**。能做什么、不能做什么，见下方「能力边界」，请先读完再动手。

---

## 一句话部署（把这句话原样丢给 AI）

> **帮我部署这个仓库：https://github.com/erzhuzi486/campus-run-assistant**
> **先读 AGENTS.md，按里面的步骤执行，直到 `python doctor.py` 全绿。**
> **需要我手动操作的（在雷电里选摄像头）再停下来问我。**

AI 会自己完成：探测环境 → 装/校验雷电版本 → 对齐实例参数 → 安装相机修复 APK → 跑验收。
全程只有**一个停顿点**：在雷电 GUI 里选摄像头设备（这一步不落盘、不写注册表，脚本无法代劳）。

如果你自己动手，等价命令是：

```bat
python doctor.py          :: 先说现在差什么
python apply_config.py    :: 对齐参数（需先关闭雷电）
python doctor.py          :: 复检，全绿即完成
```

完整步骤与原理见 [`环境复刻.md`](环境复刻.md)。

## 一、能力边界（先看这个）

### 已验证可用

| 能力 | 状态 | 实测依据 |
|---|---|---|
| 定位注入（雷电 9） | ✅ | 注入精度 ±0.000001°，无 mock 标记，191 ms/次 |
| 定位注入（雷电 14） | ⛔ 已移除 | 2026-11 起不再接管，程序只认雷电 9 |
| 1 Hz 轨迹投喂 | ✅ | 喂入与读回最大偏差 0.056 m |
| 相机真假诊断 | ✅ | 4 个信号交叉判定，见 `检查相机.py` |
| 雷电 9 使用真摄像头 | ✅ | 镜像后像素相关性 0.934 |
| 步频 / 步数 / 步幅 | ✅ | 按配速反推：步频 166–171 spm、步幅 ≈1.08 m、步数×步幅 ≈ 距离（自洽） |
| **在悦跑世界 1.1.23+ 上使用** | ⛔ **已失效** | 2026-11 初平台批量清号，按**模拟器/root 环境特征**整组封禁，与轨迹、步频做得多真无关。详见 `踩坑记录.md` 第七节 |

### 已验证不可用

| 能力 | 结论 | 依据 |
|---|---|---|
| 雷电 14 使用电脑摄像头 | ❌ | `ldcam.exe` 开相机时进程数恒为 0；HAL 请求 RGBA 返回纯色 `0x2a852a7c`；JPEG 三个分辨率输出全零 |
| 4:3 分辨率不变形 | ❌ | 640×480 是 1280×720 横向压缩 18.5% 得来 |
| 让 App 读到**系统级**步数 | ❌ | 模拟器只有 8 个传感器、没有 `TYPE_STEP_COUNTER`，需注入 `SensorManager`，本项目不做 |
| 绕过人脸活体检测 | ❌ | 不做，也不提供方案 |

### 明确不做的事

- 不修改目标 App 的安装包
- 不使用 Xposed / LSPosed 等注入框架篡改相机数据
- 不提供静态照片绕过人脸比对的方案

## 二、快速开始

### 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| 雷电模拟器 | 9.5.42（推荐）/ 14.0.32 | 只有 9 能用真实摄像头 |
| Python | 3.10+ | 需带 tkinter；Windows 建议用系统 Python |
| Node.js | 16+ | 生成与校验轨迹数据 |
| platform-tools (adb) | 任意较新版本 | 相机诊断需要 |
| ffmpeg | 任意 | 相机诊断需要（可选） |

详细清单见 `软件清单.md`。

### 三步跑起来

> **第一次装、什么都不懂**？直接看 **[`从零安装.md`](从零安装.md)** —— 从装 Python 开始，一步一步带截图级说明，20 分钟做完。
> 已经按文档装过、只想懂原理的，看 [`环境复刻.md`](环境复刻.md)。
> 环境已经装好的，先跑一句 `python doctor.py` 体检，全绿再往下走。
> **在用 AI 编程助手**（Claude Code / Cursor / Codex / Copilot）？把仓库丢给它，说一句「按 AGENTS.md 部署这个项目」，它会自己走完 检测→配参→装包→验收，只在「选摄像头」那一步停下来问你。

```text
① 启动雷电模拟器（双击桌面图标，不要用命令行启动，否则 ADB 可能不生效）
② 确认虚拟机内「开发者选项 → USB 调试」和雷电设置里「ADB 调试」都已开启
③ 双击「一键刷跑.vbs」（无黑框，推荐）或「一键刷跑.bat」
```

界面上选择跑量、配速，点「开始跑」即可看到小圆点沿跑道移动。

### 只接管雷电 9

`run_gui.py`、`run_once.sh`、`doctor.py` 等脚本**只探测雷电 9**，雷电 14 被明确排除：

- 常见安装路径列表里没有 14
- 盘符浅扫描即使扫到，只要路径含 `LDPlayer14` 就一律跳过
- 两台都装着、只开着 14 时，程序会显示「未启动」并指向雷电 9，不会误接管 14

想手动指定，仍然可以用环境变量 `LDCONSOLE` 指到任意 `ldconsole.exe`（**注意：指定 14 会绕过这个保护**）。

## 四、坐标系警告（最容易踩的坑）

校园跑类 App 在国内一般用 **GCJ-02（火星坐标）**，而模拟器的定位注入接受 **WGS-84**。

同一地点两者相差约 **500 m**，直接喂 GCJ 坐标会得到「不在围栏内」。

```text
GCJ-02  118.600939, 39.204802
WGS-84  118.595184, 39.203921      实际相差 505.9 m
```

**本项目所有坐标常量都是 WGS-84**，直接用即可。若你手里是手机地图复制的坐标，
需先转成 WGS-84，转换方法见 `技术原理.md`。

## 五、配置（一般不需要动）

程序会按「环境变量 → PATH → 常见安装目录 → 盘符浅扫描」的顺序自动找 `ldconsole.exe`、`adb.exe`、`ffmpeg.exe`。找不到时才需要手动指定：

| 环境变量 | 作用 | 示例 |
|---|---|---|
| `LDCONSOLE` | 指定 ldconsole.exe | `set LDCONSOLE=D:\LDPlayer\LDPlayer9\ldconsole.exe` |
| `ADB` | 指定 adb.exe（相机诊断用） | `set ADB=C:\platform-tools\adb.exe` |
| `FFMPEG` | 指定 ffmpeg.exe（相机诊断用） | `set FFMPEG=C:\ffmpeg\bin\ffmpeg.exe` |
| `CAMERA_NAME` | 指定摄像头设备名 | `set CAMERA_NAME=HD webcam` |
| `SERIAL` | 指定 adb 设备序列号 | 默认 `emulator-5554` |

设置后新开一个 cmd 窗口生效。

## 七、已知限制

1. **相机比例**：4:3 档位会被横向压缩 18.5%（16:9 档位正常）。补偿方案见 `技术原理.md` 第 5 节。
2. **相机稳定性**：`ldcam.exe` 偶尔"占着设备但不送帧"，表现为画面变成淡青色合成场景、日志刷 `waitRelative error: -110`。用 `检查相机.bat` 判定，恢复方法见 `使用方法.md` 第 4 节。
3. **ADB 偶发不生效**：雷电 9 用命令行启动时 ADB 可能不打开，用桌面图标启动即可。
4. **传感器缺失**：模拟器没有 `TYPE_STEP_COUNTER` 计步硬件（实测 8 个传感器里没有它）。
   界面上的**步频 / 步数 / 步幅是由配速反推的展示值**，用来核对这次跑量的合理性，不是真传感器读数。
   绝大多数校园跑 App 的步频也是从 GPS 轨迹反推的（不依赖计步器），所以定位投喂正常时 App 侧一样能算出步频；
   要让 App 读到**系统级**步数则必须注入框架改 `SensorManager`，本项目不做。
